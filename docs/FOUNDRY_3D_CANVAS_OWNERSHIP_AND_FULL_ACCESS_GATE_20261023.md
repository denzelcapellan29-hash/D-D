## Reliability failure distinction
1. **HTTP504** from first-party Bridge `/rpc` means it queued a command, but **GM/browser did not return the result before the timer**. It does not establish that Foundry or the Python MCP process crashed. Read-only `inspect_3d_capabilities` succeeded before, but a subsequent native workflow inspection returned 504.
2. **WinError10048** is duplicate Python MCP launch: Windows port 18748 is occupied by a previously running instance. Never start more listeners blindly.
3. Installed browser bridge `startPolling()` invokes `pollCommand` via `setInterval` (default1s, registered as client setting `pollMs`); `pollCommand` checks GM and active scene, gets `/bridge/next`, executes native API, posts `/bridge/result`. It uses 6s aborted fetch. Agent `/health` currently reports pending RPCs, but **does not expose a last_browser_poll_at heartbeat**. Event-driven last Scene snapshot time is **not** a reliable polling heartbeat.
4. Recommended narrow enhancement: first-party agent stores last observed `/bridge/next` request time, last result time, health adds age and GM scene/consumer; no vendor module changes. Respect freshness, avoid falsely passing stale polls. Implement/test in first-party repo and guarded deploy only after checkpoint/backups. Until then, no more blind reload/F5 or Scene.view attempts on approved map.
