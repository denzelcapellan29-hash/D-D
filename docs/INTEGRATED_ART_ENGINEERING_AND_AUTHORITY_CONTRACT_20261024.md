# Integrated art–engineering production contract
Original decision 2026-10-24; routing/coordination reconciled 2026-10-25. This contract defines method, not acceptance of an artifact.

## Current route
Blender is the editable master; native Foundry V14 + 3D Canvas is the primary playable target. For connected source-map interiors, author one independently editable area per shared coordinate system, with continuous visible surfaces, appropriate authored structure/terrain, suitable provenance-tracked assets, explicit portals and a linked master. Approved lane-specific methods are not canceled by an older blanket asset-only or no-Blender-room rule.

Use [the reproducible workflow](REPRODUCIBLE_BLENDER_FOUNDRY_WORKFLOW.md), a private build manifest, and the exact-membership preflight. Reuse settled work and valid evidence; do not restart as an unrelated pilot.

## Common representative section
Source meaning, physical structure and visible art must agree in the same actual arrangement. A structural pass with poor artwork, or attractive art with false connections, is incomplete. Preserve sound architecture while fixing the failing layer.

A representative indoor section includes connected floor, adjoining walls/corner or doorway, supported ceiling/roof and a defining narrative/wear cue. Include essential elevation/entrance connectors. Outdoors uses representative continuous terrain/bank/entry. Reuse the existing representative area/family rather than inventing a new test for every resumed task.

## Independent evidence gates
1. SOURCE: actual published layout, route, elevations, uncertainties and approved deviations.
2. STRUCTURE: evaluated contacts, bearings, clearances and support; deliberate failure controls. Bounds proximity does not prove contact.
3. ART: source-compatible silhouette/relief, coherent material family, UV/PBR continuity, varied plausible wear and preserved passage envelopes.
4. WORLD: actual matched approach, eye-height, reverse, opening/seam and overhead images; coherent surrounding space without unfinished voids or camera tricks.
5. NATIVE: early source-preserving export/import and parity, then actual token support, walls, doors, elevation/bridge/stair traversal, camera, roof/Levels, reload, performance and exact restore as applicable.

Use PASS, FAIL and UNVERIFIED. DM_ACCEPTED is a separate final artistic decision. Static metadata, saves, exports, nonblack captures, ray samples or short performance samples do not establish the remaining gates. Teleport and disabled Falling/collision are not support proof.

Known failures hold affected replication/release; independent reversible repairs may continue. Geometry changes invalidate adjoining contact/art/native evidence; material changes invalidate affected visual/export evidence, not unrelated proven geometry. Two comparable nonimproving attempts require a changed approach.

## Coordination and safety
One coordinating task may carry art/skill policy, Blender scene production and native integration roles sequentially or delegate isolated scopes. One writer per mutable artifact; no silent takeover or automatic messaging of other chats. Fixed historical chat labels are not a requirement for three chats.

Preserve accepted originals, source hashes, roles and rollback. Use native APIs before reimplementing them. Paid generation requires the provider's task-specific cost confirmation. Keep player-safe exports and GM-only reveals separate; inspect actual pixels for disclosure. In-person first-person is the default presentation; separate non-GM fog testing is not a default blocker.

## Compact review record
Record artifact/source/input hashes; exact area/master/GLB versions; geometry measures; camera/render configuration; actual image/native evidence; SOURCE/STRUCTURE/ART/WORLD/NATIVE states; DM decision; blocker; next action; owner and verified time. Private records hold private maps, actual campaign layouts and confidential review content.

Published source controls canon, latest DM choices control scope/adaptations/acceptance, GitHub controls technical implementation/tests, skills control applicable procedure, private current state selects releases, and live apps establish actual runtime behavior. Project settings UI is independent of repository/Drive edits.
