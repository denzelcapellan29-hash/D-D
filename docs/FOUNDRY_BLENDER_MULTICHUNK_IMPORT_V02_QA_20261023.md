## What was actually implemented
1. v0.2 background Blender exporter groups source MESH objects using explicit `acq_chunk` labels; any unlabelled mesh becomes its own chunk. Separates static from explicit native interactive assemblies. Preserves immutable source .blend; records full source row-major world transform and source parent name, genuine GLB source attribution, exact source hash, per-chunk GLB SHA/bytes, material names, collision/sight hints, native door extras, scene x/y center and independently calculated Tile elevation. Up to 64 chunks, explicit source-approved meshes only; rejects unbaked modifiers and unsupported visible curve/volume meshes rather than flattening silently.
2. A parented/rotated reused source stone-rim mesh revealed that transforming Blender's eight conservative `obj.bound_box` corners overestimated the actual GLB envelope: source expected 148.25×85.18px, native Three Box3 134×67px. Correction: true source vertex extrema transformed by `matrix_world` using numpy; rerun expected 134.386×66.791px, actual 134×67px. Source unchanged. Never call this an architectural scene defect.
3. Importer v0.2 verifies every source .blend and GLB hash/size, parses actual GLB JSON header, validates chunk IDs, 16-float transforms, scale and elevation, previews EVERY chunk through native `preview_native_asset_tile`, and corrects 3D Canvas Tile x/y as **center** coordinates. Strict actual apply accepts only the original inactive GM-viewed QA clone at its baseline checksum and requires created non-null Tile IDs plus native Three runtime_bounds for all chunks, with targeted semantic-ID rollback on failures. No arbitrary live Scene setting access.
4. Actual static 2-chunk Blender fixture copied/instanced existing Meshy-derived approved-source stone-rim geometry only (no new meshes), including one 19° rotated parented object with elevation offset; exported two GLBs 44,012,712 and 44,012,660 bytes; live native preflight PASS, two new live QA Tiles with IDs `gSFjMoZTYubzGI4F` and `vq8OM8nsC0Osebah` loaded and validated. Live Three bounds of rotated tile center approx (2.215,0.073568,1.101) size (0.134,0.033227,0.067); source formula and elevation numerically match.

Another disposable source .blend combined one static rim mesh with **installed library** `modules/canvas3dcompendium/assets/Tiles/Furniture/Door1.glb` (three actual mesh nodes Door, DoorFrame, DoorHandle). Each part explicitly opted into one `acq_rigid_assembly` group; exactly one part carried native door identity `doorId=qa-v02-native-door`, `doorType=1`, `doorStyle=1`, `doorState=0`. ## Honest remaining gaps / non-acceptance
- This is **not yet a complete arbitrary scene importer**: chunk assignment is source-authored and capped at 64. The new **opt-in QA reconciler** accepts idempotent create/update of exclusively v0.2-owned QA Tiles, journals every changed managed field and restores on a verified bounded failure. The original create-only v0.2 importer remains unchanged. Release beyond the pinned QA clone still requires a general safe scene lifecycle and stronger crash recovery.
- No source-matched whole-room overhead and player-eye art parity, lit material review, seam closure, entrance/collision/elevation occupancy, or benchmark across an entire Area8/Area10 Blender master; those other-instance source scenes remain out of scope.
- A door comprising frame/handle/slab has been structurally packaged, but hinge pivot/joint animation may not survive flattened GLTF parent hierarchy; native open/closed gameplay only certified historically on original library Door1 and its **swing-open failed**. Do not sell v0.2 door support as physical door QA pass.
- Unbaked Blender modifiers, authored curves, animations, more than 64 chunks, and assets lacking traceable library source need deliberate handling, not silent flattening.
- Foundry V14 Surfaces separately passed a point support fixture previously; genuine dynamic traversal of multi-elevation imported chunks is NOT certified. D&D5e `disableFalling=true` is still a deliberate world-wide workaround. Native GameCamera black render remains separate; working free-camera/FPS mode does not imply GameCamera fixed.
- Full typed operational MCP coverage of native Premium/Mapmaking editor panels, camera preview bug correction and async selection-restore patch still pending; the existing 14 Acq typed wrappers and 121 Foundry tools remain exposed.
