# Blender → 3D Canvas import spike — first real end-to-end PASS (2026-10-22)

**Classification:** Working one-asset **native geometry + placement** importer proof, with QA-only idempotent Tile and fully automated one-command dry-run. **Not yet a verified full-dungeon importer or DM-approved art parity.** No third-party code, approved source scene or accepted Blender master modified.

## Priority reaffirmed by DM
**Top priority:** A seamless, low-friction Blender → 3D Canvas flow that reliably rebuilds whatever is authored in Blender without hand-assembling a dungeon inside Foundry. 3D Canvas first-person movement and token control can be operated manually by the DM if necessary; do not let further camera/vision automation displace Blender-world import. Godot and 3D Canvas remain competing playable runtimes. Official/community 3D Canvas maps are appropriate references for native walls, collision, doors and interaction flags (not geometry provenance for our custom rooms unless assets are explicitly approved). Blender remains the creative/geometry source of truth.

## Implementation
Three first-party open-source scripts are now in GitHub:
1. [`tools/blender_to_3d_canvas/export_bundle.py`](../tools/blender_to_3d_canvas/export_bundle.py) — read-only background Blender 5.2 export of visible source MESH objects into a new centered, grounded, Y-up textured GLB, plus a JSON manifest with source Blender bounds, scale, world anchors, provenance, original mesh list, collision/door metadata and known export omissions. Changes to object transforms exist only in that disposable background Blender process; source `.blend` is not saved. This v0.1 intentionally stops if visible curves/nonmesh geometry or doors/interactive meshes would otherwise be silently baked into static geometry.
2. [`tools/blender_to_3d_canvas/import_bundle.py`](../tools/blender_to_3d_canvas/import_bundle.py) — SHA256 and file-size validation, native Foundry/3D Canvas GLB loading, native bounding-box/depth comparison, semantic-ID Tile update/create, actual loaded Three.js geometry center+size check and bounded rollback for failed imports. **The v0.1 target is restricted to the independently verified QA clone** `sW4aXZgKXj1cH0US`; never permits the approved Area 8 Scene `NUEDEFAULTSCENE0`. Preview is the default; `--apply` enables QA-only changes.
3. [`tools/blender_to_3d_canvas/run_pipeline.py`](../tools/blender_to_3d_canvas/run_pipeline.py) — single-command end-to-end orchestration of the two scripts with preflight before import, optional `--manage-qa-view` to use native GM-local `Scene.view`, initialize the 3D renderer, restore original GM Scene view and camera in `finally`, and verify original Scene SHA on exit. Supports reusing immutable staged GLBs without redundant export. Does **not** require third-party 3D Canvas vendor modifications, hand-placed Foundry Tiles or manual browser console.

## Required next gates (NOT yet done)
1. Extend exporter from one static mesh to a **source-indexed coherent room section** with multiple meshes/parents, original transforms and material dependencies, not manually rebuilt geometry. Test fixed overhead/player-eye cameras against the real Blender master, including scale/roof/wall support, joins, texturing and physical ground. Avoid importing 1.4GB/1.8GB Area8/10 main blends directly until memory/performance gate and proper checkpoint; this session observed only ~8.8GB free of 31.2GB total on Windows.
2. Distinguish static chunks vs native doors/interactive objects/ceilings/collision/sight per submesh. Official 3D Canvas GLTF extras support `collision`, `sight`, `isDoor`, `doorId`, `ds`, `doorStyle`, `doorAnimateAngle`; exploit native 3D Canvas features. Game camera/first-person automation is lower priority than faithful construction import.
3. Give the importer a general safe native Scene lifecycle rather than hardcoding the one QA clone. Include native idempotent ownership, immutable revision verification, chunked multi-GLB bundle, native upload/verify, manifest-based transforms and rollback. Existing `apply_semantic_objects` is a useful insertion primitive.
4. Run controlled **lit material comparison** with actual screenshot review (current fixture camera was too dark) and real native collision/ground checks in a purpose-built open QA fixture. Then Area 8 full scene on isolated copy and Area 10 unseen-from-3D-Canvas independent import, and benchmark against Godot. DM alone visually accepts final art.
5. Tighten `export_bundle.py` root/parent and material validation, and add automated regression tests for centering, quality, idempotency, and scene preservation. The demonstrated pipeline is only a first measurable slice, NOT "anything" yet.
