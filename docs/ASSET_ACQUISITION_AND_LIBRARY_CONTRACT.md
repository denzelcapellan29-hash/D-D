# Provider-neutral asset acquisition and our custom library

Choose the already selected provider and approved job; a new provider is a deliberate experiment, not a silent replacement. Reuse eligible existing assets first. A procedure for Meshy endpoints remains in the Meshy specialist; common asset quality requirements apply to any future provider. Exact Meshy cost approval does not transfer to another task/provider. Obey the selected provider's actual cost-consent requirements and record approved versus actual spend. Tool discovery is not installation or generation.

Before any reference or generation, inspect the relevant source text/map/art. Separate explicit appearance, contextual inference, source silence, conflict and DM adaptation. Unread/conflicting evidence blocks a source-certified claim; routine source-silent decisions can be labeled DESIGN_CHOICE within authorized scope. Keep secrets private and verify upload/use rights.

Use a valid reference for the actual endpoint. For single-image conversion: one complete isolated object, plain background, readable volume, no labels/map/collage. A same-object multiview route requires independently inspected consistent geometry and separate input files in provider-required order; an approved four-panel presentation is split only after identity validation. Never infer unseen geometry or certified dimensions from an image. Two repeated invalid-reference attempts require changing approach.

Record provider/model/version/options, source/reference IDs and hashes, task ID, immutable downloaded source hashes, rights, approved/actual costs, dimensions, axes/origin, meshes, PBR/UV maps and isolated all-side inspection. Create separately versioned art/LOD derivatives; inspect every installed-facing side, underside, contact and actual assembled connection. Compare alternatives using the same reference and scene scale, cleanup effort, source fit, native material/draw/texture cost and cost per usable result; vendor credits are not interchangeable currencies. Marketing labels such as game-ready do not certify Foundry performance.

## Library compatibility versus kit compatibility
Installed 3D Canvas 9.0.36 AssetBrowser accepts custom sources and registered asset packs. Read-only installed implementation shows `assetBrowserCustomPath`, `registerPack(packId,packName,categories,{subfolder})`, optional `index.json` containing relative paths, and explicit `registerAssets` records (`output`, optional `displayName`, `preview`, `search`). Default discovered previews use matching `.webp` basenames. Recheck these version-specific hooks before implementation; do not patch vendor files or assume registration was performed.

The browser indexing contract does not standardize every model's module size or connector. Define our own asset-family contract: meters; explicit physical bounds and axis conversion; predictable origin/ground contact and applied transforms; architectural grid/pitch where appropriate; named mating planes/openings/clearance; independent door hinge pivots; portable PBR/UV density; collision/sight/camera role tags; stable asset IDs, provenance and performance budget. The campaign commonly uses 1.524 m per 5 ft, not a universal vendor rule. Props, trees and terrain retain appropriate real dimensions. Reuse the same mesh/material files when eligible for native instancing/merge; unique models do not become mergeable by sharing a category name. Never merge doors or incompatible level/reveal boundaries.

Pack only assets with verified distribution rights; private campaign packs and public generic code have different contents. Validate library drop-in placement and an actual assembled connector in native Foundry before declaring a family standardized. Own source-matched assets can form a library without adopting another creator's floorplan or art style.

## Installed native placement and material checks
In the tested V14 / 3D Canvas9.0.36 client, Tile placement depends on anchors: the native shape minimum is document x/y minus the corresponding shape anchor times width/height; the client derives that shape from the Tile texture anchor. Use calibrated minimum coordinates with anchor0 or center coordinates with anchor0.5. A raw shape payload is not a replacement for the Tile document's texture anchors. Large terrain with negative extents must be verified against actual native bounds; the tested client clamped a negative zero-anchor placement. Do not repeat an unconditional rule that every Tile uses center coordinates.

The installed loader reported UV1 normal maps unsupported. Keep a verified portable UV0 normal atlas or separately verified compatible material route; a Blender-only second UV channel is not native PBR parity. Preserve source textures and art masters. Indexing a GLB into an Asset Browser neither verifies these behaviors nor certifies an over-reduced foliage derivative: inspect the actual isolated/assembled silhouette before repeating it.
