## Research conclusions and blockers (official sources)
1. **Meshy → Blender → FBX**: feasible. All changes must be independently versioned derivatives; no Blender-generated visible primitives. Blender batch can import approved GLB/OBJ/FBX, evaluate actual mesh vertex world positions and pivot, triangulate, decimate, UV/material QA, preserve aspect unless approved, export FBX with explicit forward/up axes and per-asset origin/size/connector metadata. It must not automatically assume full cube is filled or decimation yields exact vertex count.
2. **TaleWeaver Lite**: officially a Unity project for **creature mods only**. Official guide https://talespire.com/taleweaverlite-guide specifies single triangulated mesh, maximum 60,000 vertices (typical native creatures ~4,500, largest ~11,000), three textures at most 2048x2048, FBX accepted by Unity and packed PBR texture. Guide is creature-oriented, and default-scale/auto-positioning must be accounted for; additional settings https://talespire.com/taleweaverlite-additional-info allow disabling automatic import positioning and scaling. Its .tsMod compiler is not a verified custom architectural tile importer.
3. **Official tile/prop import remains planned**. https://talespire.com/faq ; https://feedback.talespire.com/roadmap ; https://feedback.talespire.com/p/mod-support-adding-custom-meshes-assets . DO NOT use custom Meshy architecture as tile in native slabs until a genuinely registered tile asset UUID can be confirmed inside TaleSpire after load and actual visual/collision QA.
4. **Official native Slab Format v2**: https://github.com/Bouncyrock/DumbSlabStats/blob/master/format.md ; slab is grouped asset kinds with UUID, packed positions x/y/z * 100 as 18-bit positive coordinates, 5-bit rotation (0..23 steps at 15 degrees), gzip+Base64. Creature count is always zero in published v2 format. Compatibility with the installed current build needs round-trip tests: version check, units, handedness, positive-coordinate translation, limits and paste behavior. Not direct freeform XYZ text ingest, nor a way to embed creature .tsMods in slab code.
5. **Community slab encoder precedent**: https://github.com/brcoding/TaleSpireHtmlSlabGeneration ; reference implementation exists for native assets. Stable rollout requires independently encoded trivial slab to paste, round-trip and compare geometry.
6. **TaleSpire Symbiote API** currently documents no persistent board state edits; see https://symbiote-docs.talespire.com/ . Do not claim a native official API to place entire rooms programmatically. A one-paste, one-board-slab import is the initial practical minimum interaction.
7. **Unofficial Custom Assets Library Plugin (CALP)** https://thunderstore.io/c/talespire/p/PluginMasters/Custom_Assets_Library_Plugin/ has version 3.5.5 last updated 2023. Its own asset type table explicitly marks Prop and Tile '**Not yet implemented in CALP**', and Slab only partial. Modded assets remain experimental/compatibility risk, not a reliable solution until tested on the current TaleSpire build. Treat mods as an isolated optional research track.

## Two independent components with a strict contract
**A. Blender batch processor (background mode):**
- Inputs folder and manifest: file source hash, asset role, nominal grid footprint (1x1,2x2 etc), desired standing height/roof bearing, visual facing direction, connector frames, performance tier and asset revision. Results only in staging area; NEVER overwrite original Meshy GLBs.
- Import, isolate mesh objects, apply evaluated world transforms or operate on copied consolidated geometry (triangles; UVs preserved), report nonmesh/armatures, absent textures, degenerate faces, finite coordinates, bounds and actual max dimensions.
- Base anchor in Blender Z-up: a=((minX+maxX)/2,(minY+maxY)/2,minZ) **in source frame**. Transform independent vertices so bottom-center is local origin; verify evaluated world bounds after transforms/FBX reimport. 'Set Origin to Geometry' alone is incorrect. Protect source geometry with derivative versioning.
- Uniform fit s=min(targetX/extX,targetY/extY,targetZ/extZ). This fits **inside** envelope but does not fill all three axes. Force-fitting each axis stretches/distorts and breaks connectors, disallow by default. If the required footprint/structural interfaces are incompatible, FAIL asset contract and request new Meshy source.
- Iterative target decimation with absolute triangles + vertices + UV/PBR fidelity and silhouette constraints. Do NOT confuse decimate 'face ratio' with guaranteed vertex count. Initial creature profile limits <60,000 vertices, with lower preferred budgets for reused modules; tile geometry budgets not officially specified here.
- PBR texture conversion: albedo + normal + packed metallic/AO/emissive/smoothness channels per CURRENT TaleWeaver Lite guide; max 2K for creatures, 1K LOD recommendation where suitable. Reimport FBX into a test Blender file and compare normals/UV texture links and dimensions; export independent FBX with axis conversion consistent with Unity Y-up.
- Sidecar metadata includes original/FBX SHA, bounds local/world, footprint, true contact connectors, pivot, facing orientation, triangle and vertex counts, texture checksums, import scale behavior and QA images. The .tsMod remains a separate Unity/TaleWeaver compiler stage; asset UUID is recorded only after a true TaleSpire import/registration readback.

**B. Canonical room blueprint JSON / MCP:**
- Independent of runtime. Coordinates are integers x,z = horizontal square-cell min corner and y = quarter-cell elevation; grid horizontal pitch=1 TaleSpire grid unit, y=0.25 TaleSpire units. Catalog stores asset ID, kind (native_tile, native_prop, imported_creature, unsupported_custom_tile), true footprint and collider/connector masks, bottom-center pivot and adapter offset, revision/hash. Placements: unique instance id, catalog key, `grid:{x:int,y:int,z:int}`, `yaw_steps:0..23` with 15-degree step. Right angles use steps 0,6,12,18. Each asset also carries structural role and collision policy; compiler must reject unknown UUIDs or unsupported kinds.
- Resolve exact registered uuid from catalog. Before encoding slab verify role, horizontal footprint after rotation, connector normals, walkable support height, unintended penetration, collision profile and structural adjacency. Intentional wall-to-floor contacts must not be rejected as volume overlaps, and surface AABB touching alone does not certify continuity.
- Native slab adapter converts semantic positive/negative coordinates to nonnegative relative positions using a translation offset, handles centering pivots and scale, version-specific packing and gzip/base64. Calibrate by exporting/pasting one built-in tile from installed TaleSpire and inspecting round trip.
- Imported creature .tsMod assets are a distinct placement channel, since v2 slabs do not encode creature placements. Do not conflate a creature Asset ID and registered native Tile/Prop UUID.

## Go/no-go proof-of-concept gates
P0: snapshot TaleSpire install/profile/build and note any existing installed mods; do not change campaign.
P1: native index parser and 2x2 floor/wall mock blueprint, collision/occupancy validation against exact installed ColliderBoundsBound; generate slab; paste into disposable TaleSpire board; screenshot + rotation/height QA and encode/decode roundtrip. This path can deliver **native kit automated room layouts** without custom geometry.
P2: one independently derived approved Meshy GLB decimated/bottom-center/axis-converted FBX through TaleWeaver Lite Unity (if installed) to .tsMod creature; verify model PBR/scale/base/visualization in TaleSpire. Distinguish decorative proxy from a structural Tile/Prop.
P3: if custom architectural tiles are mandatory, require explicit native support or experimentally successful and maintainable isolated alternative; currently **not supported through official TWL**. No entire-episode migration until custom 1x1 floor + two walls + a door are actually recognized as native Tile/Prop kinds, slab-encoded, visually inspected, structurally navigable and multiplayer-safe.

**Verdict**: Blender automation and native kit slab rooms are feasible. Custom Meshy structural architecture → official TWL .tsMod → automatic native TaleSpire tile slab is NOT currently established/supported. Publish no claims of full custom room feasibility until P3 PASS. Do not resume Foundry production without new DM decision.
