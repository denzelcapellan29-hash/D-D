## Explicit DM direction
User proposes a TaleSpire-like assembly workflow for genuine custom Meshy assets, with Foundry/3D Canvas as the actual playable and cinematic scene, avoiding full scene duplication in Blender. ## Architecture — one authoritative assembly
Official source / keyed map → semantic room and travel blueprint → asset-family registry with exact approved Meshy original GLBs, source SHA/lineage and measured interface connectors → **Foundry-first builder** (asset palette / snapping / prefab placement) → persisted Foundry Scene Tiles + Foundry environment/lights/walls/tokens/GM secrets → genuine 3D Canvas hero/structural imagery and playable-QA. Blender is a **per-asset** workstation (isolated multiview QA, bounded derivative/LOD, PBR, GLB export, measurable contact frames) or an **optional cinematic offline exporter**, not a default second scene assembly target. The semantic layout, not Blender .blend or Minecraft block objects, drives all exporters.
