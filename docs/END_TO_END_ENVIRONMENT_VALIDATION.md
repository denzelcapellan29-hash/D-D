# Proving a source-to-playable environment workflow

Use this when validating a production method or making a substantial generator/runtime change. Routine repairs should reuse still-valid evidence instead of restarting this entire experiment.

## A bounded proof with four distinct results

1. Build a decorated, connected source slice from a frozen interpretation and immutable asset/material inputs into an empty output. Include a working portal, level change, secret or trap if relevant, and an irregular boundary when the source needs one. Finished indoor room shells cannot count as freshly generated architecture. Retained exterior or props are valid reuse, explicitly identified.
2. Rebuild the identical inputs with the identical recipe into another empty output and import it into a separate private native scene. Compare actual exports, then check the fresh import. Do not compare `.blend` bytes, timestamps, or manifest claims alone.
3. Apply the same engine to a different small source layout, then make one bounded revision. Preserve source facts, label inferred dimensions, and verify both intended changes and unaffected neighbors. An empty source room must remain empty. This demonstrates transfer within that construction domain; it does not establish arbitrary cave, terrain or biome support.
4. Test the expected full-location load separately. A synthetic geometry/miniature budget is useful for residency, culling and rendering costs, but cannot certify the source layout, gameplay, simultaneous visibility or art of a complete location.

Freeze the acceptance contract before measuring. Keep SOURCE, STRUCTURE, ART/WORLD, NATIVE_GAMEPLAY, LIGHT/VISION, PERFORMANCE, CLEAN_REBUILD, TRANSFER, REVISION, PORTABLE_RELOAD and DM_ACCEPTED separate. Every result names its exact input, output and native revision. Unperformed checks remain UNVERIFIED. Final visual acceptance belongs to the DM.

## Dependable authored geometry and exports

Use one calibrated plan for area envelopes, physical elevations, stair treads, pits, roof/ceiling ownership and portal states. Keep source-shaped irregular features. Generate complete enclosed construction rather than repairing independent caps by eye. Continuous PBR finishes, real relief and suitable source props are part of the decorated candidate.

Inspect the exported meshes against an independently registered source overlay. Use actual transformed upward triangles and leaf centers, not just manifest bounds. Include a deliberately shifted opening or support mesh and verify the relevant check fails. Registration is finite geometric evidence; a person still checks source interpretation and appearance.

Inspect closed leaves with actual rays across several heights and lateral offsets. Visible planks with gaps can admit the native movement ray; a continuous core may be needed. Test the same assembled door open and closed, including hinge pivot and paired leaves. Recompute metric UVs on treads, risers, caps and returns; scaling a textured box is not a stair finish.

Check enclosure below raised landings and outer stair flights as well as top support. Test diagonal corner bearings and wall bases against the lowest actual graded floor, not only a room's nominal elevation. A supported walking route can still reveal open construction from a neighboring view. Keep deliberately defective earlier meshes as negative evidence for these independent checks.

Preserve approved imported assets' collision, sight and camera roles. Do not blanket-enable those roles after joining dressing. Group only compatible semantics; keep interactive leaves, secret reveal geometry, non-shadowing detail, water and distant decorative context separately controllable. Separate editable assemblies from runtime packaging. A giant distant mesh sharing a batch with dungeon architecture defeats useful culling; indiscriminate microtile splitting can instead increase draw calls.

Sort imported objects, join inputs and exported membership to make outputs repeatable. Hash the actual immutable inputs and final files. Byte equality is the strongest simple check; when file bookkeeping differs, compare transformed triangle geometry, UVs, materials, images and role metadata with a stated tolerance. A bounded revision must change only the expected semantic set. Keep failed attempts and their diagnoses as project evidence rather than adding incident histories to the skill.

## Native proof and useful review controls

Native tests use ordinary controlled-token movement with actual support and collision in both directions. Test closed blocking, open passage, oblique approaches, stairs/landings, secret clear/restore, pit depth, exploration and recovery. Relocation is setup or a labelled GM review aid, never traversal or character climbing evidence.

Click the real rendered controls as well as testing document state. Dialog actions can have reserved names; confirm the installed API and verify the resulting leaf angle after animation settles. Restore original locked/ajar/hidden states. Test lantern off/on, exterior and free-view restoration, and re-entry on the same current scene. Darkness cannot conceal structural or art defects; separate brighter inspection captures from the actual gameplay light.

Validate the installed native placement schema before promising exact coordinates. If document coordinates are integer-only, use a verified native fractional offset where available and report remaining dimension quantization. Small placement errors can hide a shallow mural or create overlapping finishes. Include panorama/environment images in the hashed deployment dependency set alongside models and reveal variants, then reopen the renderer before judging the installed environment.

Cover finite source-grid stances, borders, treads and useful viewing headings. Record unsupported, occupied, excluded and unresolved positions separately. Any alternate stance remains within the same review square and on the same level, with the reason retained. Downward and upward views reveal defects missed by horizontal routes. Contact sheets are explicitly reduced previews; inspect full native images for flagged defects, clues and representative art.

Normal review controls should use the local runtime controller directly and work after temporary test services stop. Keep private destinations, door controls, lantern, walk/free view and pit recovery discoverable without overwriting the user's hotbar. Guard scene ownership/version and provide teardown that restores temporary presentation and resolution changes.

## Valid performance measurements

Measure actual native frames after warmup at fixed pose, movement, lighting, quality, focus, hardware and resolution. Read the WebGL context's actual canvas dimensions. A detached Three renderer element, requested scale or composer size can disagree with the real shared PIXI/Three drawing buffer. Assert the intended physical buffer remains stable throughout every sample; invalidate mismatches instead of calling them a full-resolution pass.

Use bounded reversible renderer changes when needed; inspect the installed shared-context implementation and restore both renderers on exit. Never assume one application's setting controls the actual output or permanently change global quality to improve a score. Avoid background builds and UI interference during timed samples.

Report average FPS, median/p95/p99 frame time, draw calls, triangles including shadow passes, actual buffer, GPU, quality and moving/standing route. Average 60 FPS and p95 at or below 16.67 ms are distinct outcomes. High small-slice FPS is neither whole-location certification nor proof that modular construction universally improves performance. Reject visually damaged optimizations even when faster.

## Efficient execution and honest delivery

Use one build entry point and one configured controller rather than accumulating permanent repair macros. A successful process exit is insufficient: require completion receipts and export preflight. Commands and evidence are written atomically; use unique request IDs, bounded retries for reads and explicit pending status. Inspect actual state before repeating a mutation whose result is unknown.

Measure source interpretation, asset preparation, clean generation, repair, native QA and final review separately. A five-minute generation stage after hours of interpretation and repair is not a five-minute finished environment. Record transfer/revision time and rework to find the next real bottleneck. Cache verified unchanged dependencies and retest affected neighbors.

Deliver an editable master, immutable inputs, pinned recipes/assets, portable exports/configuration, evidence index, review controls and exact rollback. Reopening native 3D is different from a cold client restart or import into another world; verify each claimed level. Publish only the reusable method and nonprivate code to shared sources. Keep campaign maps, coordinates, GM clues and captures private.
