# Repeatable source-to-runtime production

Use the selected location and current DM scope. Keep the official source, source interpretation, approved changes, as-built geometry and acceptance separate. This procedure improves reuse; it does not promise automatic art or certify any scene.

## Source specification and components
Extract one versioned location specification: adventure/site/area IDs; source page/map locators and source hashes; one coordinate calibration; room/terrain outlines; floor/ceiling/elevation facts and uncertainty; openings, states, ownership and intended circulation; material/identity anchors; required props and private GM reveals. Reuse this verified specification downstream. Reopen source when new scope, conflicting evidence or an unresolved consequential choice requires it. Do not repeatedly reread unrelated histories. Ask the DM only when the remaining choice materially affects approved fiction, play or cost.

Select existing source-compatible components by verified scale, sockets, PBR, art and runtime behavior. Catalog our own accepted components and assets; reuse does not authorize a generic stock-kit substitution. Numerical structure owns openings, bearings and connectors. Terrain/caves use their appropriate real mesh construction. Asset generators supply artwork and props, not dimensional evidence. Preserve originals, independent moving doors/reveals, globally aligned editable areas and linked assembly.

## Connected batches and automation
Prioritize the next reachable branch. Reuse the existing representative decorated connection and valid checks, then expand a meaningful connected area batch. Resolve source/structure/art/native failures in their causal layer before broad replication. Keep fixed player-eye/reverse/overhead views and native parity on the same revision.

Use validated generators and export/import adapters with stable semantic IDs, explicit roles, hashes, transforms, measured materials and reversible QA. Rebuild/reimport changed sections and their dependencies. Missing automation is work to implement, not an invented command or claim that an inventory checker completes a build. Record failures and KEEP/REVERT; two comparable nonimproving attempts warrant a different method. No vendor patches or disabled collision to manufacture passes.

## Dependency-aware checks
| Change | Minimum affected evidence |
| --- | --- |
| Base color or ordinary roughness only | Matched art and native material views; inspect appearance and any changed render cost |
| Normals, displacement, alpha, transmission, shader or LOD | Art/silhouette/seams, export parity and performance; support/sight where evaluated geometry, opacity or collision changes |
| Geometry, placement, scale, hierarchy, pivot or connector | Source layout, evaluated support/bearing/clearance, actual negative control, neighbors, native affected routes and camera |
| Door state/tags or sight/collision metadata | Native blocked/open/reclosed behavior, sight, support and affected movement routes |
| Level/Region/visibility/light configuration | Actual vertical transitions, enclosure, secrets, illumination, native parity and performance |
| Runtime/exporter changes or uncertain impact | Broader dependent regressions and reload; do not assume unchanged outputs |

Keep valid evidence only when its exact inputs and dependencies remain unchanged. Every location release still needs an assembled source/art review, actual native walking including reverse/elevation/blocked controls, doors, camera, reload, secrets and representative moving-view performance. Rays, teleport, document updates, inventory and disabled Falling are not traversal proof. Verify authored-state restoration and protected-source preservation.

## Compact current state
Keep a short manifest-backed summary: selected versus last accepted artifact paths/hashes, linked membership/dependencies, current installed versions, gate results and evidence links, deferred items, DM decisions/cost approvals and next reversible action. Archive incident histories. Update it at milestones; public GitHub stores generic method/code while private records store campaign source, assets and secrets. Verify remote writes before claiming sync. Project settings require a separate explicit change.

Measure source work, construction, cleanup, export/import, verification and rework separately. Evaluate throughput by completed source-faithful playable areas and repair rate, not generated model count or short-version suffix.
